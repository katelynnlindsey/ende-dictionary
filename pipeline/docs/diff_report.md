## Bugs found and fixed during the port (before this diff went clean)

1. **Sense definitions were losing literal `~` characters.** The original `senses2tex` extracts each sense's definition with a bare `''.join(definition.itertext()).strip()` -- bypassing the `cleanstr()` helper that every other field goes through. `cleanstr()` strips `~` (it exists to clean up stray combining-diacritic byte sequences). My first port applied `cleanstr` uniformly and silently dropped `~` from ~17 definitions (e.g. "type of pandanus with long fruit (~2 feet)" -> "...(2 feet)"). Fixed by giving `Sense.definition` its own raw-text extraction path that skips `cleanstr`, matching the original exactly.
2. **First-vs-last-wins on multi-relation entries.** 17 entries have more than one `_component-lexeme` relation with a `complex-form-type` trait. The original's `complexformof2tex` takes the *first* one found (`break` after the first match); my first pass took the *last* one. Fixed to match.

## Pre-existing dead-code paths reproduced as-is (confirmed inert on this data, not fixed)

These are latent issues in the **original** code, not introduced by this refactor. They are reproduced faithfully rather than silently fixed, since fixing them would be a content/behavior change:

- `\lexeme{}`, `\relforms{}`/`\relformiqu{}`/`\relformen{}`, and the irregular-possessed-form macros never fire on this export (0 entries have the underlying LIFT fields: no entry has a `citation` form distinct from its `lexical-unit` form, no `RelatedForms` field exists, no irregular-possessed-form variant exists).
- The verb-specific per-sense POS branch (`senses2tex(..., sense_pos=True, ...)`) never fires: the comparison `get_first_pos(entry) in verb_pos` always compares a capitalized LIFT value (e.g. `"Intransitive verb"`) against an all-lowercase list, so it's always False. Every entry (verb or not) goes through the entry-level `pos2tex` + sense-level-without-POS branch instead. Practical effect: **a multi-sense verb entry whose senses have different POS values (e.g. one transitive, one intransitive) will only ever show the first sense's POS for the whole entry.** Worth knowing about, not changed without your say.
- `\relforms{}`/`\irregthirdposs{}`/`\irregfirstposs{}` contain a pre-existing double-backslash typo in the original source (`r'\\relformiqu{'` etc.) that would print as a stray line-break + literal macro name rather than invoking a command, if the branch ever fired. It never does on current data.
